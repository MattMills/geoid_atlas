# GeographicLib reference data

These expected values are external reference fixtures, not generated by the
`geoid-atlas` implementation under test. Tests run without network access.

- `GeographicLib-20.dat`: the 20 high-precision reference cases in Charles
  Karney's [official Python geodesic test suite](https://github.com/geographiclib/geographiclib-python/blob/1598d357b8edd456e3f01ab5acf47ae27c2e331e/geographiclib/test/test_geodesic.py).
  Extracted by parsing its `GeodesicTest.testcases` literal, retaining all 12
  columns in order: lat1, lon1, azi1, lat2, lon2, azi2, s12, a12, m12, M12, M21, S12.
- `GeodTest-100.dat`: the unmodified 100-row subset of Karney's published
  [GeodTest dataset](https://geographiclib.sourceforge.io/html/geodesic.html#testgeod)
  distributed as [geographiclib-rs v0.2.7's fixture](https://github.com/georust/geographiclib-rs/blob/v0.2.7/test_fixtures/GeodTest-100.dat).
  Its 10 columns are lat1, lon1, azi1, lat2, lon2, azi2, s12, a12, m12, S12.
  It includes nearly coincident, polar and nearly antipodal paths. This is a
  subset; we do **not** claim to run the complete 500,000-row GeodTest dataset.

The wrapper tests check both direct and inverse distance/azimuth/endpoint
behavior. Very short or conjugate paths can have poorly conditioned azimuths
after rounding the input endpoints to f64. For the 100-row set, inverse azimuth
checks use the reference reduced length m12 to turn angle error into transverse
metre error; direct endpoints are also checked in metres. The 20-case suite
checks angular values directly. Additional published `GeodSolve6/9/10/11/33/73/78/99`
regressions are reproduced with their original tolerances in `tests/geodesics.rs`.
